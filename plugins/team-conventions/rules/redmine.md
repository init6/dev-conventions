## Redmine 運用規約

タスクは Redmine で管理する（GitHub Issues ではない）。
Redmine のホスト・プロジェクト ID は環境によって異なるため、**具体的な URL / project id は各リポジトリの `CLAUDE.md` を参照する**。

### チケットのライフサイクル
- タスクはまず Redmine に**起票**する。すべての作業をチケットに紐づける。
- タスクに**着手するとき**に、担当者を自分に設定し、ステータスを「進行中」に変更する。
- **完了** … PR をマージしたら、紐付く Redmine issue をクローズ状態（完了扱い）に更新する。ステータス名は環境により「終了」「完了」等と異なるため、ID は `GET {host}/issue_statuses.json` で確認する。`refs #<番号>` で PR とチケットが関連付く。マージ実施者（または担当者）が更新する。
- **後片付け** … クローズしたら、そのチケットのために作った **worktree とローカルブランチを削除する**（[並列作業の推奨](parallel-work.md) の「後片付け」を参照）。
- Claude に作業を指示する場合も、担当者は**指示した本人**とする（Claude を担当者にしない）。

### API 操作（curl）
- 起票・更新・コメントは Redmine REST API を curl で実行できる。
- 認証は各自の `~/.zshrc` に export した環境変数 `REDMINE_KEY` を使い、ヘッダ `X-Redmine-API-Key: $REDMINE_KEY` を付与する。
- **非対話シェルは `~/.zshrc` を読まない**ため、コマンド内で `source ~/.zshrc` してから使う。
- **API キーの値はコミットや会話（PR 本文・チャット等）に出さない。**
