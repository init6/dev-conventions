## 並列作業の推奨（git worktree / 並列エージェント）

待ち時間を減らすため、**互いに依存しない作業は並列化する**。

### git worktree の利用を推奨
- 複数のチケット/ブランチを並行して進めるときは、`git stash` ＋ブランチ切替で行き来せず、**git worktree** で作業ツリーを分ける。
  ```sh
  git worktree add ../<repo>-task-604 task/604   # ブランチ用の作業ツリーを別ディレクトリに作る
  git worktree list                              # 一覧
  git worktree remove ../<repo>-task-604         # 不要になったら削除
  ```
- 利点: ブランチ切替に伴う作業ツリーの巻き戻し（未コミット変更の退避）やコンテキスト喪失を避けられる。レビュー対応と新規実装、複数チケットを同時に進められる。
- Claude Code では起動時の `--worktree` や、サブエージェントの `isolation: worktree` でも同等の分離ができる。**並行して同じファイルを触る場合はこれを使う**（作業ツリーを分けて衝突を防ぐ）。

### エージェントの並列利用を推奨
- 互いに依存しない作業（複数箇所の調査・独立した実装・観点別レビューなど）は、**サブエージェントを並列に起動**して同時に進める。逐次実行より待ち時間が短い。
- 切り分けの原則: 依存関係のある作業は直列に、独立な作業は並列に。結論だけ必要な広範な探索・レビューはとくに並列化の効果が大きい。
- ファイルを同時に書き換える並列作業は、上記の worktree（`isolation: worktree`）でツリーを分けてから行う。
