PR がマージされた後の締め処理を一括で行う。Redmine 運用規約・デプロイ規約に従う。

## 0. 対象の特定
- チケット番号は引数 `$1`、無ければ現在/直近の作業ブランチ名 `task/<番号>` から取る。取れなければユーザーに確認する。
- 対象の PR が実際に **マージ済み** であることを確認する（`gh pr view` 等）。未マージなら中断して知らせる（land はマージ後の処理）。

## 1. Redmine issue を完了（クローズ）に
- ホスト/プロジェクトは各リポジトリの `CLAUDE.md` から解決（`redmine` スキル参照）。認証は `source ~/.zshrc` + `REDMINE_KEY`、**キーは出さない**。
- クローズ状態の `status_id` を `GET {host}/issue_statuses.json` で確認（名称は環境により「終了」「完了」等）。
- `PUT {host}/issues/<番号>.json` で `status_id` をクローズに更新し、`notes` に PR の URL を添える。

## 2. worktree とローカルブランチを片付ける
- `git worktree list` で棚卸しする。**このチケットのために作った worktree を削除する**（`.claude/worktrees/` 配下の Claude Code 製も対象）。
- **削除前に失われるものが無いか必ず確認する。**
  - 未コミットの変更: `git -C <パス> status --porcelain` が空か
  - リモートに無いコミット: `git log --oneline origin/<デフォルトブランチ>..<ブランチ>` が空か
  - どちらかが残っていれば **削除せず**、何が残っているかを伝えて判断を仰ぐ。
- `git worktree remove <パス>` → マージ済みブランチも `git branch -d task/<番号>` で消す（`-d` は未マージなら失敗するので安全）。
- **`--force` / `-D` は使わない。** 失敗するのは安全装置なので潰さない。
- 自分がいま中にいる worktree は削除できない。先に元のディレクトリへ戻る（Claude Code なら `ExitWorktree`）。
- ついでに、他のチケットの**マージ済みなのに残っている worktree** が無いかも見て、あれば同じ手順で片付けてよいか確認する。

## 3. デプロイ（本番がブランチ追従の構成のときのみ・要確認）
- 本番が特定ブランチ（多くは `develop`）を追従してデプロイする構成なら、マージ＝リリースまで一気通貫にするため本番デプロイする。
- **対象サーバー・ブランチ・実行コマンドを提示して確認してから** `/deploy` の手順で実行する。
- 本番が自動追従でない構成、または変更が本番ランタイムに影響しない（docs のみ等）場合はデプロイしない。その旨を伝える。

## 4. 報告
- 完了にしたチケット番号、削除した worktree / ブランチ、デプロイの有無・結果を報告する。
