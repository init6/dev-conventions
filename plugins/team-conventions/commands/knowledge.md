「次回以降・別端末・他メンバーでも知っておくべき」知見 `$ARGUMENTS` を、**git 管理の md に追記**して共有する（Claude Code の memory 機能には保存しない）。

## 1. 記録先を決める
このリポジトリの `CLAUDE.md`「知識共有」方針に従って記録先を選ぶ。
- **蓄積していく業務知識**（調査結果・仕様メモ・気づき・ハマりどころ等） … 専用の知識ファイル（例 `docs/knowledge.md`）があればそこ。無ければ `README` / `docs/` に相応の md を用意する。
- **恒久的なルール・判断基準・プロジェクト方針** … `CLAUDE.md` に追記する（毎セッション読み込まれるため）。
- 判断に迷う内容なら、どちらへ書くかユーザーに一言確認する。

## 2. 追記する（書式を揃える）
- **1 項目 = 1 見出し（`###`）**。新しい知見はファイル**末尾**に追記する。
- 見出しは内容が分かる簡潔な名前。関連チケットがあれば `— #653` のように併記する。
- 本文には次を含める（分かる範囲で）:
  - **絶対日付**（例 `2026-07-24`。相対日付は使わない）
  - 関連する**チケット番号 / PR / ファイルパス**
  - 「何が起きたか → 原因 → どうしたか（対処・結論）」が追える記述
- 一時的なメモ・その場限りの内容は書かない。

## 3. 反映
- 追記後、差分（どのファイルに何を足したか）を要約して報告する。
- コミットは規約に従う（`refs #<番号> ...`）。知識の追記は通常の作業コミットに含めてよいし、独立コミットでもよい。**コミットするかはユーザーに確認**してから行う。
